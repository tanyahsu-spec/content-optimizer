# 內容稽核報告輸出格式

輸出稽核結果時,使用以下結構。以下用 `[ ]` 標示需要填入的內容,實際輸出時請移除方括號並填入真實資料,不要留下模板痕跡。

---

## 使用範例

```markdown
# SEO / AEO / GEO / AIO 內容稽核報告

**稽核對象**:[文章標題、產品介紹或網址]
**目標關鍵字**:[關鍵字,若使用者未提供則寫「依內容推斷:___」]
**稽核日期**:[日期]

## 總覽

| 面向 | 分數 |
|---|---|
| SEO(傳統搜尋) | [X]/100 |
| AEO(語音助理/精選摘要) | [X]/100 |
| GEO(生成式引擎:ChatGPT/Perplexity) | [X]/100 |
| AIO(Google AI Overview) | [X]/100 |

[一到兩句話總結整體狀況,例如:內容本身資訊紮實,GEO 表現佳,但缺乏 meta 標籤與標題階層規劃,SEO 與 AIO 分數明顯偏低。]

---
```

## 撰寫報告時的原則

- **每一項結果都要有依據**:不要只寫「✅ 符合」,要附上「因為原文第 X 段有寫 Y」這種可驗證的說明,讓使用者能對照原文檢查。
- **建議要能直接照做**:避免「請加強 SEO」這種空話,改寫成具體句子、具體格式範例。
- **分數要誠實**:嚴重缺失(如完全沒有標題階層、完全沒有作者資訊、頁面被 noindex)就該給低分,不要為了報告好看而灌水。
- **優先項目要真的有排序邏輯**:不是把四份清單的不符合項目全部條列出來,而是先想清楚「改哪一項對可見度提升最大、又最容易做到」——技術性的守門項目(如 AIO 的索引問題)通常該排最前面,因為不解決,其他優化都難以生效。
